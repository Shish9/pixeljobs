# Testing

| Layer | Command | Covers |
| --- | --- | --- |
| Types | `npx next typegen && npm run typecheck` | strict TS, typed routes, dictionary completeness |
| Lint | `npm run lint` | Next + TS rules |
| Unit | `npm test` | Arabic-Indic digit and Arabic-comma input parsing, package/project/proposal schemas, status rules mirroring DB triggers, browse-filter whitelisting, DB error mapping, locale matching, path localization, IQD/number/date formatting incl. Western-digit preference, dictionary parity, zod schemas (quick onboarding, optional username), open-redirect guard, image magic-byte sniffing, HTML→text sanitizer, profile completion |
| E2E | `npm run test:e2e` | all 4 locales render with correct `lang`/`dir`, locale redirect, language switcher, protected-route redirects, bad auth-callback handling, city picker (keyboard, filter, empty state, Escape), search submit + invalid city fallback, mobile tab bar, localized server-side validation, wrong-password error from real Supabase, no horizontal overflow in all 4 languages (desktop + Pixel 7), **axe WCAG 2.1 AA** on 11 pages, policy pages in all 4 languages |
| E2E (signed in) | `E2E_EMAIL=… E2E_PASSWORD=… npm run test:e2e -- tests/e2e/account.spec.ts --project=desktop` | sign-in → quick onboarding (mode + city) → dashboard next steps + mode tabs → username/profile save → avatar upload → spoofed-file rejection → Western digits on a Kurdish page → privacy → guest-page bounce → admin 404 (or admin view with `E2E_EXPECT_ADMIN=1`) → sign-out |
| E2E (marketplace) | `E2E_FREELANCER_EMAIL=… E2E_CLIENT_EMAIL=… E2E_PASSWORD=… E2E_FREELANCER_USERNAME=… npm run test:e2e -- tests/e2e/marketplace.spec.ts --project=desktop` | two people, one run: publish refused without a package (values kept), service with Arabic-Indic price, portfolio, profile details, client search → save → request, project with budget validation (values kept), freelancer accepts request and proposes with portfolio, client shortlists and accepts → project Assigned, saved list, public profile |
| E2E (trust & safety) | `E2E_FREELANCER_EMAIL=… E2E_CLIENT_EMAIL=… E2E_MODERATOR_EMAIL=… E2E_PASSWORD=… E2E_FREELANCER_USERNAME=… npm run test:e2e -- tests/e2e/trust.spec.ts --project=desktop` | three people: request opens a conversation, unread badge, reply, completion, blind two-sided reviews (hidden until both written), public rating, report a message, moderator sees only the reported copy (conversation itself is 404), hides it, action log, client sees it removed, non-staff 404 on admin |
| RLS (trust) | paste `supabase/tests/rls_trust.sql` into the SQL editor | 56 checks: auto-created conversations, participant-only messages, no sender spoofing/editing, proposal first-message rule, unread counts, closed threads, staff cannot browse messages, review gating + blindness + stats, report snapshots/duplicates/self-report, moderate() permissions (moderators cannot act on admins or themselves), hide/restore message, owner cannot re-publish a suspended listing |
| RLS (marketplace) | paste `supabase/tests/rls_marketplace.sql` into the SQL editor | 34 checks: publishing gates, staff-only statuses, unconfirmed-email block, anon visibility, party-only requests/proposals, snapshot pricing, own-service/own-project blocks, portfolio ownership, duplicate proposals, accept → assigned, illegal transitions, daily limit, media folder isolation |
| RLS | paste `supabase/tests/rls_foundation.sql` into the SQL editor | 38 checks as anon, client, private user, new user, moderator, admin. Always ends with `RLS_TESTS_PASSED (38 checks)` and rolls everything back. |

Sandboxes without Playwright's pinned browser: `PW_CHROMIUM_PATH=/path/to/chrome npm run test:e2e`.

The signed-in suite needs a **confirmed, not-yet-onboarded** account. Create one in a dev/staging project (Auth →
Users → Add user, "Auto confirm"), run the suite, then delete the user. Do not keep test accounts in production.
